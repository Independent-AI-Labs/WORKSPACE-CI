# Audit: Capability Loss via Deletion Commits

**Date:** 2026-08-24 (backdated scope 2026-08-23)
**Auditor:** workspace-agent
**Status:** Complete; restorations landed, two items open

## Scope and Method

Systematic differential of every deletion made by the four
capability-loss commits against the current tree, classified as:

- **superseded**: the deletion was intentional and correct; a reviewed
  replacement exists.
- **dead-reference**: nothing referenced the deleted surface anymore;
  deletion was safe.
- **dropped-capability**: live consumers or latent need remained; the
  deletion removed working capability and left hazards.

Deletion commits reviewed: `f7422dc` (19 files), `89cd3e1` (11),
`b4210cf` (4), and the `a37d062`-era partial deletion inside
`lib/checks_files.sh` (function-level, not file-level).

## Findings

### F-1 `f7422dc: scaffold subsystem (dropped-capability)

Deleted: `scripts/scaffold-ci`, `lib/scaffold_lib.sh`,
`lib/scaffold_analyze.sh`, `templates/Makefile.consumer`,
`templates/ci-profile.template.yaml`, five test suites, REQ/SPEC docs.

The commit message called the scaffold "retired", but no replacement
existed. Consequence realized 2026-08-22: GATEWAY's
`.pre-commit-config.yaml` was regenerated by the stale `../CI` clone
(a pre-f7422dc checkout), silently reintroducing unreviewed-path
references into a consumer config. The capability vacuum was filled by
an unsanctioned source.

Latent breakage found at restoration: the tier field had also been
dropped from `parse_hook_yaml.awk` profile mode (scaffold-ci could
never parse any profile), and `safety: true` markers had been dropped
from `required_hooks.yaml` (poc tier filtered out its own safety
hooks).

**Restored:** `a0efdec` (code, templates, tests; unit tests relocated
under `tests/unit/scaffold/` to respect the per-module file limit) plus
guarded-interface catalog edits (safety markers, operator session
2026-08-24). End-to-end probe verified generation.

**Open:** REQ-SCAFFOLD-CI.md and SPEC-SCAFFOLD-CI.md not yet restored;
rewrite from current behavior rather than copying stale text.

## Pattern Summary

Every dropped-capability deletion shares one signature: **the commit
message described intent ("retired", "historical baggage") rather than
consumer state.** Nothing verified remaining consumers at deletion
time. The `a37d062` deletion-consumer gate and the `80089d2` entry
integrity gates now close the file-level and function-level variants;
field-level catalog drift remains open.
